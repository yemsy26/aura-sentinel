# Apps de escritorio con Tauri 2 (Rust + web, 2026)
- Versiones: `version("tauri", "crates")` y `version("@tauri-apps/cli", "npm")`. Usa la misma versión mayor (2) en `tauri`, `tauri-build`, `@tauri-apps/api` y `@tauri-apps/cli`.
- NO uses `tauri init` ni `npm create tauri-app`: hacen preguntas interactivas y fallan sin consola (y `init` no sirve si ya existe `src-tauri`). Escribe tú la estructura:
  - `package.json` en la raíz: scripts `"dev": "vite"`, `"build": "tsc && vite build"`, `"tauri": "tauri"`; dependencia `@tauri-apps/api`; devDependencies `@tauri-apps/cli`, `vite`, `typescript`.
  - `index.html` en la raíz con `<script type="module" src="/src/main.ts"></script>` y el código en `src/main.ts`. `vite.config.ts`: `export default defineConfig({ clearScreen: false, server: { port: 1420, strictPort: true } })`.
  - `src-tauri/Cargo.toml`: `[build-dependencies] tauri-build = "2"` y `[dependencies] tauri = "2"`, `serde = { version = "1", features = ["derive"] }`, `serde_json = "1"`.
  - `src-tauri/build.rs` (obligatorio): `fn main() { tauri_build::build() }`.
  - `src-tauri/src/main.rs`: `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` y en `main`: `tauri::Builder::default().invoke_handler(tauri::generate_handler![get_stats]).run(tauri::generate_context!()).expect("error al iniciar la app");`.
  - `src-tauri/tauri.conf.json` (formato de Tauri 2): `{"$schema": "https://schema.tauri.app/config/2", "productName": "Mi App", "version": "0.1.0", "identifier": "com.miempresa.miapp", "build": {"devUrl": "http://localhost:1420", "frontendDist": "../dist", "beforeDevCommand": "npm run dev", "beforeBuildCommand": "npm run build"}, "app": {"windows": [{"title": "Mi App", "width": 900, "height": 600}], "security": {"csp": null}}, "bundle": {"active": true, "targets": "all", "icon": ["icons/32x32.png", "icons/128x128.png", "icons/icon.ico"]}}`. Sin `app.windows` la app arranca SIN ventana. Las claves de Tauri 1 (`tauri`, `distDir`, `devPath`, `allowlist`) no valen en Tauri 2.
  - `src-tauri/capabilities/default.json`: `{"identifier": "default", "windows": ["main"], "permissions": ["core:default"]}`. Da permisos al núcleo y a los plugins (cada plugin añade el suyo, p. ej. `"opener:default"`). Los comandos propios registrados en `generate_handler!` se pueden invocar sin más.
  - Iconos: en Windows la compilación exige un `src-tauri/icons/icon.ico` válido. Después de `npm install` (la CLI viene de npm), en la raíz: crea el PNG con `powershell -c "Add-Type -AssemblyName System.Drawing; $b = New-Object Drawing.Bitmap 1024,1024; [Drawing.Graphics]::FromImage($b).Clear([Drawing.Color]::FromArgb(30,60,120)); $b.Save((Join-Path (Get-Location) 'app-icon.png'))"` y luego `npx tauri icon app-icon.png`, que genera todos los tamaños en `src-tauri/icons`. No hagas el `.ico` a mano ni renombres un PNG: la ventana saldría sin icono.
- Comandos: `#[tauri::command] fn get_stats() -> Stats` con `#[derive(serde::Serialize)] struct Stats { .. }`. Devuelve el struct tal cual: Tauri lo convierte a JSON y en JS llega como objeto (`const s = await invoke<Stats>("get_stats"); s.cpu`). No devuelvas `serde_json::to_string(...)` como `String`: llegaría un texto y `s.cpu` valdría `undefined`. Los nombres de los campos son los del struct (`cpu_usage` sigue siendo `cpu_usage` en JS). Con argumentos, las claves van en camelCase: `fn saludar(nombre_completo: String)` se llama con `invoke("saludar", { nombreCompleto: "Ana" })`. Para errores, devuelve `Result<T, String>` (en JS llega como excepción).
- Estado compartido: `.manage(Mutex::new(Estado::default()))` en el Builder y `fn cmd(estado: tauri::State<'_, Mutex<Estado>>)` en el comando.
- Frontend: `import { invoke, isTauri } from "@tauri-apps/api/core";`. En Tauri 1 era `@tauri-apps/api/tauri`, y `@tauri-apps/api/invoke` no existe. Para saber si corre dentro de la app usa `isTauri()`: `window.__TAURI__` solo existe con `"app": {"withGlobalTauri": true}`, así que con el paquete de npm es falso también DENTRO de la app. Fuera de Tauri (abriendo la página en el navegador), muestra un aviso en vez de fallar. Sin bundler, usa `withGlobalTauri: true` y `window.__TAURI__.core.invoke(...)`.
- Medidas del sistema con `sysinfo`: el uso de CPU se calcula entre dos refrescos, así que crear un `System::new_all()` nuevo en cada llamada da 0 % siempre. Guarda el `System` en el estado (`Mutex<System>`) y refréscalo en cada llamada. La API cambió entre versiones (sin traits `*Ext` desde la 0.30): comprueba la tuya con `version("sysinfo", "crates")` e investigar antes de escribir.
- CLI: `npm install` en la raíz instala `@tauri-apps/cli`. Después, `npx tauri dev` abre la ventana con recarga y no termina; `npx tauri build` deja el instalador en `src-tauri\target\release\bundle`. No existe el crate `cargo-tauri` (el de la CLI es `tauri-cli`, que tarda en compilar): usa la de npm.
- Comprobar sin abrir ventana: `cd src-tauri && cargo build` (la primera vez compila unas 400 dependencias y tarda minutos) y `npm run build` para el frontend. La ventana no la puedes ver: no lances `npx tauri dev` salvo con `fondo=true`, y detenlo al acabar.
- run.bat: `crear_bat("run", ["npm install", "npx tauri dev"])`. build.bat: `crear_bat("build", ["npm install", "npx tauri build"])`.
- `verificar` compila `src-tauri` (cargo build y test) y revisa la configuración: ventana definida, `build.rs`, `identifier`, `frontendDist`, icono válido, `__TAURI__` sin `withGlobalTauri`, que cada `invoke("x")` del frontend tenga su `#[tauri::command]` en `generate_handler!` y que `invoke` se importe de la ruta de Tauri 2.
