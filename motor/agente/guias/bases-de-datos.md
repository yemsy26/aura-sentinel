# Bases de datos (PostgreSQL, MySQL, MongoDB, Redis, SQLite)
- En local con Docker: un `docker-compose.yml` con un servicio por base, volumen con nombre, `healthcheck` y contraseñas desde `.env`:
  `postgres: image: postgres:17` + `environment: POSTGRES_PASSWORD: ${PG_PASSWORD}` + `volumes: [pgdatos:/var/lib/postgresql/data]` + `healthcheck: test: ["CMD-SHELL", "pg_isready -U postgres"]`. MySQL: `mysqladmin ping`; MongoDB: `mongosh --eval "db.runCommand('ping')"`; Redis: `redis-cli ping`. Etiquetas reales con `version("postgres", "docker")`.
- Arranca y espera a que estén listas: `docker compose up -d --wait`. Sin cliente instalado, entra por el contenedor: `docker compose exec -T postgres psql -U postgres -c "SELECT 1"`, `docker compose exec -T mongo mongosh --eval "..."`. SQLite no necesita servidor (módulo `sqlite3` de Python o `sqlite3.exe`).
- Conexión por variable de entorno (`DATABASE_URL`), nunca escrita en el código; `.env` en .gitignore y `.env.example` sin valores.
- Esquema SOLO con migraciones: Alembic (Python + SQLAlchemy 2), Prisma o Drizzle (Node), EF Core (`dotnet ef migrations add`), sqlx (Rust), golang-migrate (Go), Flyway (Java). Cada cambio, una migración con su vuelta atrás.
- Consultas siempre parametrizadas (nunca concatenar texto del usuario: inyección SQL), índices en las columnas de WHERE y JOIN, paginación, transacciones para escrituras que van juntas.
- Varias bases a la vez (otra plataforma o motor): una variable por conexión (`DATABASE_URL_PRINCIPAL`, `DATABASE_URL_ANALITICA`) y un módulo de acceso por base. Para copiar o sincronizar datos entre motores: script que lee por lotes de una y escribe en la otra dentro de transacciones, convierte los tipos (SQLite `INTEGER PRIMARY KEY AUTOINCREMENT` → PostgreSQL `GENERATED ALWAYS AS IDENTITY`, booleanos, fechas en UTC) y al final compara recuentos y sumas de control.
- Base remota (servidor, nube): conectarse con psql/mysql/mongosh/redis-cli o con una URL `postgres://`, `mysql://`, `mongodb+srv://`... a otra máquina pide permiso al usuario. Antes de migrar una remota: copia de seguridad (`pg_dump -Fc`, `mysqldump`, `mongodump`) y prueba la migración en una copia local.
- Borrar datos (`DROP`, `TRUNCATE`, `DELETE` sin WHERE, `FLUSHALL`, `docker compose down -v`, `docker volume rm`) pide permiso.
- Tests contra una base temporal (SQLite en memoria o un contenedor de prueba), nunca contra la real; cada test deja la base como estaba.
